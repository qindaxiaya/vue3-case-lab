# 案例完成标准（Definition of Done）

> 适用范围：**新案例严格执行**；存量案例按批次渐进补齐。
> 每个案例收尾时逐条勾选，并在提交说明或走查记录中留下证据。
> notes.md 五段模板见 `docs/templates/notes.md`。

## 1. Demo 可运行与稳定性

- [ ] 开发服务器打开案例页，首屏可交互，无白屏、无死循环
- [ ] 连续刷新 3 次：无未捕获异常、无 `[Vue warn]`、无资源 404、无未处理 Promise rejection
- [ ] 路由往返后状态正确（例：先看 raf-loop 再进其他案例，代码区不得为空）
- [ ] 离开页面后无残留 rAF、定时器、Observer 继续执行
- [ ] 证据：dev 地址 + 控制台截图 + 往返路径记录

## 2. 错误 / 正确对比

- [ ] Demo 内提供「错误做法 / 正确做法」切换（二态开关或并排对照）
- [ ] 切换后能直接看到行为或性能差异，不是只换文案
- [ ] 切换控件带 `aria-pressed`，两种模式标签明确
- [ ] 不适用时：在 `notes.md` 第 5 段「边界」写明原因
- [ ] 反例：只有两段说明文字、没有可操作对比，不算达标

## 3. 真实测量数据

- [ ] 至少 1 组同任务、同数据量的 before / after 对比
- [ ] 数据由 Demo 运行时产生，不是硬编码文案
- [ ] 指标带单位：ms / FPS / DOM 节点数 / 字节数 / 事件次数
- [ ] 提供「重置 / 重测」，结果可复现
- [ ] 非性能类案例可用行为指标替代（DOM 数、事件触发次数、请求数、包体积），并在 notes 第 5 段注明「无性能差异」
- [ ] 证据：`notes.md` 第 4 段表格 + 测量方法说明

测量方法至少写清：

| 项 | 要求 |
|----|------|
| 指标定义 | 测的是什么，从哪一刻到哪一刻 |
| 采集方式 | `performance.now()` / `PerformanceObserver` / `Blob.size` / DOM 计数 |
| 数据规模 | 条数、节点数、字节数 |
| 环境 | 浏览器版本、设备、是否开启 CPU 节流 |
| 取样 | 同一操作 3 次取中位数 |

禁止编造数字；示例表格里的数字不能直接抄进 notes。

## 4. notes.md 五段式

- [ ] 文件位于 `src/examples/<category>/<case-id>/notes.md`
- [ ] 五段齐全，顺序固定：
  1. 现象 / 场景（一句话 + 复现步骤）
  2. 原理（2~4 段，Vue 内部 + 浏览器机制，讲「为什么」）
  3. 方案：关键代码（10~30 行，与 Demo.vue 一致，标 3 处「为什么写在这里」）
  4. 数据对比（表格 + 测量方式，禁止编数字）
  5. 追问与边界（Q/A ≥3 条、踩坑 ≤3 条、适用边界）
- [ ] 第 3 段以函数名/变量名为主定位，行号只作辅助（避免代码改动后失真）
- [ ] notes.md 不参与 registry，不要求站点展示

## 5. meta.ts

- [ ] 必填字段：`id` / `title` / `difficulty` / `tags` / `summary` / `sell`
- [ ] `id` 与目录名完全一致
- [ ] `tags` 3~5 个，中英文写法与同类案例保持一致
- [ ] `summary` 一句话，≤40 字
- [ ] `sell` ≤30 字，包含「解决什么问题 + 为什么选它」，20 秒内可口述
- [ ] 使用 `satisfies CaseMeta`，无多余字段

## 6. 移动端 375px

- [ ] DevTools 375×667 下 `document.documentElement.scrollWidth <= 375`
- [ ] Demo 根节点、按钮、日志区不横向溢出、不重叠、不被裁切
- [ ] 代码区 / 表格允许自身横向滚动，但不能撑破页面
- [ ] 触控目标建议不小于 32×32
- [ ] 证据：每个案例至少一张 375px 截图

## 7. 类型与工程

- [ ] `npm run type-check` 0 错误
- [ ] `npm run lint` 0 warning
- [ ] `npx vitest run` 全部通过
- [ ] `npm run build` 成功
- [ ] Demo.vue 无 `any`
- [ ] `code/*.txt` 片段自洽：import 齐全、无重复声明、无未定义变量、类型标注完整
- [ ] 新案例能被 registry 自动收录，`code/*.txt` 位于 `code/` 子目录

## 8. 交付与提交

- [ ] 更新 `AGENTS.md` 当前进度
- [ ] 一个任务 / 一个案例一个 commit，Conventional Commits + 中文描述
- [ ] 提交前跑完第 7 条全部命令，并保留输出
- [ ] 有页面变化时给出 dev 地址与走查路径，等人工确认后再继续

## 豁免与存量处理

- 存量案例的 notes.md、对比开关、真实测量按批次补齐，不阻塞新案例
- 任何豁免必须写进 `notes.md` 第 5 段，不接受口头豁免
- 无法量化的案例（纯层级 / 纯 API 用法）用行为指标或结构对比替代，仍需给出真实数据
