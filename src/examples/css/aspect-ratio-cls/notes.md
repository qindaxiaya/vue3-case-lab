# aspect-ratio 图片占位防抖动

## 1. 现象 / 场景

图片在加载前不知道自己的尺寸，元素高度是零：等图片加载完成猛然撑开，下方正文、按钮被顶下一跳——移动端读图文页时全页反复「跺脚」，阅读位置被顶丢。

复现步骤：

1. 打开案例，保持「无占位（旧）」模式，点「触发图片加载」：8 张图从 600ms 起逐张就位，观察下方内容区被顶动，「跳动次数」逐步累积、「累计布局偏移分数」上涨。
2. 切到「aspect-ratio 占位（推荐）」模式重测一次：外层在图片到来前就摆好 16 比 9 的高低，加载只是往里填图，跳动次数与偏移分数大幅回落（理想为 0）。
3. 先点「重置」再重复测量，可任意多轮复现；「已加载图片」达到 8/8 后本轮结束。

## 2. 原理

布局偏移（layout-shift）统计的是「可见元素在两帧之间相对视口位置改变」的综合量：偏移面积占比乘以移动距离占比得到单次 `value`，并且浏览器对点击/输入 500ms 之内的移动自动豁免（`hadRecentInput`）——那是用户预期内的动作，不算页面抖。

裸图片的跺脚根因在布局阶段：浏览器要在图片解码完成后才能确定它的内在宽高，此前该元素高度为零、不占位置；图片到位 ⇒ 高度从 0 突变成宽度 ÷ 原始比例 ⇒ 其后所有元素整体下移，一次偏移成立。图片越多、延迟越散，"阶梯式顶动"越密集。

`aspect-ratio` 把比例提取进样式的静态信息里：布局阶段就能用「当前宽度 × 比例倒数」算出占位高度，图片加载完成后只是把内容填进已存在的框（object-fit 控制裁切）。如果素材的实际比例与声明一致（本案例素材就是 320×180 = 16 比 9），填充阶段没有任何位移——这正是占位起效的条件；比例不匹配时仍会有一小段修正位移。

## 3. 方案：关键代码

以 `ph` 占位框与 `setupShiftObserver`（Demo.vue）定位：

```css
/* 1. 为什么占位要写在图片加载之前：aspect-ratio 是布局阶段的
      静态信息，图片元素还没到场时外层即可算出高度 */
.ph {
  aspect-ratio: 16 / 9;
  overflow: hidden;
  min-width: 0;
}

.ph img {
  /* 2. 为什么 height: 100% + object-fit: cover：图片「填框」
      而不是「撑框」，自然尺寸不再参与布局 */
  display: block;
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

```ts
// 3. 测量口径：豁免点击引起的位移，只统计页面自发的抖动
function setupShiftObserver(): void {
  shiftObserver = new PerformanceObserver((list) => {
    for (const entry of list.getEntries()) {
      const shift = entry as unknown as LayoutShiftEntry
      // 为什么先过滤 hadRecentInput：点击后 500ms 内的位移是
      // 用户预期动作（浏览器豁免），计入会污染分数
      if (shift.hadRecentInput) continue
      if (shift.value <= 0) continue
      clsScore.value += shift.value
      shiftCount.value++
    }
  })
  shiftObserver.observe({ type: 'layout-shift', buffered: false })
}
```

## 4. 数据对比

| 指标 | 错误（无占位） | 正确（16 比 9 占位） | 测量方式 |
|------|----------------|----------------------|----------|
| 累计布局偏移分数 | 每张图加载完成汇聚一次正向偏移 | 0.000（占位比例与素材一致时） | `PerformanceObserver('layout-shift')`，过滤 `hadRecentInput` 后累加 `value` |
| 跳动次数 | 与逐张加载次数同源（至少数张） | 0 | 偏移条数中 `value > 0` 的个数 |
| 已加载图片 | 0→8 张递增 | 同左 | 赋源完成计数 `loadedCount` |
| 下方内容区 | 被顶动 | 静止 | 目视对照（面板里固定文案区） |

测量说明：

- 指标定义：「累计布局偏移分数」指本轮触发加载起，所有豁免点击后仍发生的布局偏移 `value` 之和（浏览器标准口径，取 3 位小数）；「跳动次数」为其中 `value > 0` 的条数。
- 采集方式：`PerformanceObserver` 实时监听 layout-shift 条目；不使用 buffered 回放开场条目，每轮从零累计。
- 数据规模：每轮 8 张 320×180 本地 data URI 图，延迟自 600ms 起每张 +180ms。
- 环境：Chrome / Edge 近两年版本（需支持 layout-shift 观察与 aspect-ratio）；本地离线运行，无网络参与。
- 取样：可重复多轮，每轮分数由同一延迟曲线驱动、可复现；具体数值以 Demo 面板实测为准，不以本档任何写死数字替代。
- 本机一次实测（Chrome 153，1400×1000，页面可见、Demo 滚入视口）：无占位 8 张图跑完为 **0.059 / 2 次**，切到 16 比 9 占位后同一操作是 **0.000 / 0 次**。页面在后台标签页时浏览器不产生偏移条目，量到的 0 不能当结论。
- 延迟下限定在 600ms 的原因：浏览器对点击后 500ms 内的偏移豁免，太短的延迟会让偏移错过积分窗口，测量失真。

## 5. 追问与边界

**Q：aspect-ratio 和给 img 写 width/height 属性，用哪个？**
两个机制都能提前知道比例。原始图片的元数据已知时优先 width/height 属性（信息随资源走）；比例已知但尺寸未知（响应式封面、用户上传）用 aspect-ratio。都会推导出相同的占位高度。

**Q：偏移分数剔除点击是标准行为吗？**
是。`hadRecentInput` 标记为 true 的偏移不影响分数，这是浏览器对「用户预期动作」的豁免；做测量时同样要主动过滤，否则按钮触发的重排会被误计。

**Q：图片比例和占位比例不一致会怎样？**
object-fit: cover 会裁边填满、不产生位移；若用 contain 或直接让图参与布局，则会补一次修正位移。占位比例应与设计稿的实际媒体比例一起定，别凭感觉写 16 比 9。

**Q：首屏图片还能做什么？**
首屏关键图直接预加载（link rel="preload"）、写明宽高；懒加载图务必占位。占位解决「抖」，预加载解决「晚」，两件事正交。

踩坑：

1. 触发条件：占位外层没限定 `overflow: hidden` 且图片比例不匹配 → 现象：图片晚到时把占位框撑破 → 修法：占位框固定比例 + 图片填框（width/height 100%）。
2. 触发条件：测量时把按钮点击引起的渲染位移一并计分 → 现象：分数虚高 → 修法：过滤 `hadRecentInput`，并让延迟超过豁免窗口（500ms）。
3. 触发条件：data URI 生成的图像比例与占位比例不一致 → 现象：对照实验里「占位版」也出现小位移 → 修法：让素材比例与声明比例一致（本案例 320×180）。

边界：本案例是真实的性能指标（布局偏移）实测，但数字依赖本机浏览器与延迟曲线，notes 不替 Demo 写死数值；若目标环境不支持 layout-shift 观察器（老浏览器），退化方案是以 DOM 位置变化做自定义监测。图片素材为本地画布生成，因此数据里「无网络延迟」属预期，不以此反推真实网络图谱。
