# clamp 流体字号

## 1. 现象 / 场景

响应式大标题被写成好几档媒体查询：档位之间窗口收窄时，标题「啪」地一下从 40px 跳到 34px——肉眼可见的硬台阶；档位之间的宽度全被四舍五入浪费，每调一版字号都得重新挑一遍数字。

复现步骤：

1. 打开案例，切到「断点式（旧）」：从右往左拖动把手，观察「标题字号（实测）」——在 760/620/480/360/0 五个档位间直接跳变，「断点条数」显示 5。
2. 切到「clamp（推荐）」：继续来回拖动，字号读数随宽度连续滑动，停在 16.0px 与 40.0px 之间的任意中间值，「断点条数」恒为 0。
3. 直接缩放浏览器窗口效果相同：预览容器随页面宽度重排，字号照常渐变（只跟容器，不跟视口）。

## 2. 原理

`clamp(min, val, max)` 收敛规则：`val` 小于 `min` 取 `min`，大于 `max` 取 `max`，否则取 `val` 本身。把 `val` 换成**随容器连续变化的相对值**（本案例 `8cqi`，即容器宽的 8%），产出就是一条从 16px 到 40px 的连续字号曲线——下限上限封死两端，中间不再需要任何「档位」来近似。

字号驱动链路：预览容器声明 `container-type: inline-size` → 浏览器确定容器宽度 → `cqi` 相对值解析成绝对 px → clamp 三值收敛 → 样式计算给出最终字号。整个链条都在样式阶段完成，阈值由公式而非人工表格决定，所以「改变最小/最大字号」只改一个声明的两端数字，「改斜率」只动中间系数。

断点式做法是把连续曲线人肉采样成阶梯：档位数量随断点数线性增加，档位内部「宽度变了字号纹丝不动」，跨越档位的瞬间渲染值阶跃——既是视觉跳变，也是维护负担。

## 3. 方案：关键代码

以 `preview--clamp` 与 `measureFontSize`（Demo.vue）定位：

```css
.preview {
  /* 1. 先让参与驱动的元素成为容器：否则 cqi 退回按视口求值，
        容器一被挤窄字号就跟不动了 */
  container-type: inline-size;
}

.preview--clamp {
  /* 2. 一条声明：下限 1rem(16px) / 相对值 8cqi / 上限 2.5rem(40px)。
        为什么中间值选 8cqi：容器 500px 时恰好 40px 到顶，
        斜率符合标题观感；正文小字建议另用 2cqi 量级 */
  font-size: clamp(1rem, 8cqi, 2.5rem);
}
```

```ts
// 3. 指标读数：读计算样式，不信任声明——断点式的「跳」与
//    clamp 式的「连续」必须在真实渲染值上验证
function measureFontSize(): number {
  const el = titleRef.value
  if (!el) return 16
  // parseFloat 掉 'px' 单位后缀，拿到数字回显到指标条
  return parseFloat(getComputedStyle(el).fontSize) || 16
}
```

## 4. 数据对比

| 指标 | 错误（断点式） | 正确（clamp） | 测量方式 |
|------|----------------|----------------|----------|
| 断点条数 | 5 条（760/620/480/360/兜底） | 0 条 | 静态统计：案例内置断点表条数与 CSS 声明数量 |
| 标题字号 | 仅 16/23/28/34/40 五个离散值 | 16.0~40.0 连续渐变 | `getComputedStyle(标题).fontSize` 实测回显，保留 1 位小数 |
| 容器宽度 | 实时 | 实时 | `ResizeObserver` 回调内读 `getBoundingClientRect().width` |
| 字号-宽度曲线 | 阶梯（档内水平、跨档阶跃） | 线性（宽度每变 1px 字号变 0.08px） | 同一拖动轨迹下对照实测读数曲线 |

测量说明：

- 指标定义：「断点条数」为代码层面的静态规则数；「标题字号（实测）」为浏览器样式计算输出的最终字号，以标题元素的计算样式为准。
- 采集方式：`ResizeObserver` 监听可拖宽预览容器，回调内同步读取宽度与渲染字号；策略切换不改变容器宽度，RO 不回调，切换后等待两帧再重读。
- 数据规模：1 组标题 + 正文，预览容器在 220px ~ 舞台宽度之间拖动。
- 环境：Chrome / Edge 近两年版本（需支持容器查询单位 cqi），拖动把手或直接缩放浏览器窗口均可复现。
- 取样：字号随宽度连续变化，属连续读数；取「同一宽度显示同一读数」为复现标准，无时间类采样，不报中位数。
- 以 Demo 面板实测为准；本案例无时间类性能数值。

## 5. 追问与边界

**Q：clamp 里放 vw 行不行？和 cqi 差在哪？**
放也能跑，但驱动对象变成视口：组件被挤进侧栏时字号不动。cqi 跟容器走，才是组件级流式的正确旋钮；整页推广位可以用 vw。

**Q：为什么中间值是 8cqi 这个「奇怪」的系数？**
斜率决定手感：容器 500px 时 8cqi 正好顶到 40px 上限，是个实用的经验起点；斜率过大小屏很快贴下限、过小则大屏永远到不了上限。先用线性估算再用极端宽度校对。

**Q：正文也跟着缩会不会挤到看不清？**
下限封在 1rem 之外（正文 0.55em ≈ 8.8px 时已低于可读线）。惯例是正文用更小的斜率或干脆固定 rem，只让视觉锚点（主标题）做流式——本案例正文选 0.55em 是为同源演示。

**Q：clamp 能用在字号之外的属性吗？**
能，任何长度类属性（间距、圆角、图标宽）都是同一套收敛规则。典型组合是间距 `clamp(0.75rem, 2vw + 0.5rem, 1.5rem)`。

踩坑：

1. 触发条件：忘了给容器声明 `container-type` → 现象：cqi 按视口解析，挤进侧栏没变化 → 修法：容器声明补回，或确认驱动对象确实是视口。
2. 触发条件：clamp 下限上限写反或同值 → 现象：字号恒为定值 → 修法：保持 min ≤ max，用 min/max 函数拆开排查。
3. 触发条件：把 clamp 声明和断点表的行内字号同时生效 → 现象：行内样式优先级更高，clamp 永远不生效 → 修法：像 Demo 一样按模式二选一，切换时同步撤掉行内绑定。

边界：本案例对比的是「连续 vs 阶梯」的版式行为与断点维护成本，两种写法的渲染开销同级，无性能差异可测，第 4 段故用行为指标（断点数、离散值集合、曲线形状）替代性能数值。对照开关的适用前提是目标环境支持容器查询单位。
