# Clipboard 写入与降级复制

## 1. 现象 / 场景

一句话：复制功能在某个环境（非安全上下文、无授权、老浏览器）里直接抛错误，用户只能手动选文段复制，页面还看不出是哪一档能力缺失。

复现：

1. 打开案例，保持默认「分级降级」，点「复制一次」：日志显示落在哪一层成功。
2. 打开「模拟老旧环境」再复制：第 1、2 级都会失败，第 3 级兜底照样成。
3. 切到「无降级」模式重复：第一次环境缺失就直接报错收场。
4. 点「连测 10 次」：两种策略的成功率差距直接呈现在面板上。

## 2. 原理

浏览器剪贴板能力分三层：最新的 `ClipboardItem` 可以用 Blob 按类型（text/html、text/plain 等）打包富文本；`navigator.clipboard.writeText` 只写纯文本；更老一代的 `document.execCommand('copy')` 配合一个隐藏输入框，不依赖安全上下文与授权，兼容面最广（命令本身已标记废弃但依旧普遍可用）。

前两层都要求「安全上下文」（如正式域名，localhost 默认算安全）与用户手势配合，授权被拒或接口缺失时会抛拒（NotAllowedError 等）。因此稳健实现是显式试探：从高级往下逐层尝试，记录当前落在哪一层，全失败时给用户一句明示文案（而不是报错白屏）。

读取接口（`read`）权限被浏览器管控得更严，常被拒绝；但用户手动 Ctrl+V 到输入框走的是天然的用户输入通道，永远可用——所以「验证复制结果」更可靠的方式是先看层级记录，再配合手动粘贴框。

## 3. 方案：关键代码

```ts
// 1. 富文本：html 与 plain 各塞一份 Blob，客户端按支持程度取用
const htmlBlob = new Blob([RICH_HTML], { type: 'text/html' })
const plainBlob = new Blob([PLAIN_TEXT], { type: 'text/plain' })
await navigator.clipboard.write([
  new ClipboardItem({ 'text/html': htmlBlob, 'text/plain': plainBlob }),
])

// 2. 分级试探：catch 里不把错误抛给用户，继续下探
await writeRichText()            // 第 1 级：富文本
await writePlainText()           // 第 2 级：纯文本

// 3. 兜底：隐藏输入框选中后走老命令；它不挑安全上下文
area.style.position = 'fixed'
area.style.opacity = '0'
document.body.appendChild(area)
area.select()
document.execCommand('copy')
document.body.removeChild(area)
```

## 4. 数据对比

| 指标 | 无降级 | 分级降级 | 测量方式 |
|------|--------|----------|----------|
| 连测 10 次成功率（真实环境） | 见面板（富文本被拒时为 0，如 0/10） | 见面板（通常 10/10） | 面板连测 10 次统计 |
| 连测 10 次成功率（模拟老旧环境） | 0/10（环境缺接口直接失败） | 通常 10/10（第 3 级兜底生效） | 同上 |
| 当前层级落点 | 只有第 1 级一个落点，失败则空 | 1 / 2 / 3 都可能，面板实时显示 | `lastLevel` 面板读数 |
| 读取接口尝试 | — | 成功或被拒均有明示提示 | 面板读取区反馈 |

测量说明：

- 环境：现代 Chrome / Edge 桌面端；「模拟老旧环境」是显式开关（剥离前两级能力），用来在授权宽松的本地环境里也能实证兜底链路。
- 成功率统计是「重测即可复现」的真实计数（每层成败按接口是否抛错记录），不是写死的演示文案。
- 复制耗时非本案例关注点，无性能差异（行为指标：成功率与层级）。

## 5. 追问与边界

**Q：为什么不直接 try/catch 一个 ClipboardItem 就完事？**
被拒的环境里用户什么都复制不到；分级降级还能借老命令完成复制，按钮始终「可用」。

**Q：execCommand 都废弃了还能用吗？**
官方标记废弃，但浏览器出于兼容性目前仍普遍支持，且是「无授权场景」下唯一的通用兜底——用的时候心里记着这根线。

**Q：读取接口什么时候能成？**
在页面获得剪贴板读取授权（或用户明确允许）时成功；失败属于常见正常路径，读不到就提示手动粘贴，不要反复弹权限。

踩坑：

1. 在 `await` 串了一堆逻辑之后才调复制 → 丢失用户手势，接口抛 NotAllowedError → 点击回调里尽快触发复制。
2. 隐藏输入框用 `display:none` → 部分浏览器选不中 → 用 position:fixed + opacity:0。
3. 复制失败直接 alert 一堆堆栈信息 → 用户看不懂 → 文案固定一句「请手动选中复制」并给可选中的内容。

边界：本案例不覆盖读取整张图片/多件富媒体的场景（`read` 按 MIME 逐件处理，思路相同）；「模拟老旧环境」是教学用的显式开关，真实环境的第 1、2 级成败取决于浏览器与系统设置，以面板日志为准。
