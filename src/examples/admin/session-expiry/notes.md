# SessionExpiry：别让用户填到一半被踢下线

## 1. 现象 / 场景

用户正在填长表单，会话悄悄过期，点提交才被踢回登录页，填的内容全丢了；有的系统倒计时到 0 还留着普通按钮，点了没反应。

复现步骤：

1. 打开案例，剩余 6 秒、阶段活跃，没有警告条。
2. 等一两秒点「模拟活动」，剩余回到 6 秒，活动计数变成 1。
3. 继续等，剩余 2 秒时出现警告条，阶段变成即将过期。
4. 点「继续使用」，阶段回到活跃，剩余 6 秒，警告条消失。
5. 点「退出登录」，阶段变成已过期，普通操作收起，只留「重新登录」。
6. 点「重新登录」回到活跃；点「重置」把活动计数也清零。

## 2. 原理

会话过期不是突然发生的，它可以拆成三个阶段：活跃、即将过期、已过期。每个阶段能做什么不一样，界面要跟着状态切换，而不是只显示一个倒计时数字。

活跃阶段允许用户操作，任何活动都可以重置倒计时；即将过期阶段先提醒，并只开放续期入口；已过期阶段普通操作全部收起，只留重新登录。

活动只在活跃阶段生效。警告态已经进入「要不要续期」的确认，如果这时随便点一下页面又偷偷续命，用户永远看不到提醒。

## 3. 方案：关键代码

```ts
const SESSION_SECONDS = 6
const WARN_SECONDS = 2
const TICK_MS = 1000

/**! 倒计时状态机：active → warning → expired，到 0 立刻停表 */
function startTimer(): void {
  stopTimer()
  timer = window.setInterval(() => {
    if (phase.value === 'expired') {
      stopTimer()
      return
    }
    remaining.value = Math.max(0, remaining.value - 1)
    if (remaining.value === 0) {
      phase.value = 'expired'
      stopTimer()
    } else if (remaining.value <= WARN_SECONDS) {
      phase.value = 'warning'
    }
  }, TICK_MS)
}

/**! 活动只在 active 生效：警告态已经进入续期确认，不能靠活动偷偷续命 */
function touch(): void {
  if (phase.value !== 'active') return
  remaining.value = SESSION_SECONDS
  activityCount.value++
  startTimer()
}

onMounted(startTimer)
onUnmounted(stopTimer)
```

三处关键选择：

1. 用阶段而不是只存剩余秒数：按钮能不能点、警告条显不显示，都从阶段派生。
2. 活动只在活跃阶段重置：警告态和过期态不能靠点击偷偷续期。
3. 卸载时停表：否则回调会去改已经销毁的页面状态。

## 4. 数据对比

| 操作 | 剩余秒数 | 阶段 | 警告条 | 活动计数 | 测量方式 |
| --- | --- | --- | --- | --- | --- |
| 重置后 | 6 | 活跃 | 无 | 0 | 页面 data-stat 读数 |
| 等 1.2 秒 | 5 | 活跃 | 无 | 0 | 同上 |
| 模拟活动 | 6 | 活跃 | 无 | 1 | 倒计时重新开始 |
| 进入警告 | 1~2 | 即将过期 | 有 | 1 | 轮询到阶段变化 |
| 继续使用 | 6 | 活跃 | 无 | 1 | 续期 |
| 退出登录 | 0 | 已过期 | 无 | 1 | 普通操作收起 |
| 重新登录 | 6 | 活跃 | 无 | 1 | 回到初始倒计时 |
| 重置 | 6 | 活跃 | 无 | 0 | 活动计数清零 |

测量说明：

- 环境：本机 Chrome，案例页 `/cases/admin/session-expiry`。
- 取样：npm run check:ui -- --base http://localhost:5174 --only 会话过期 的常驻场景。
- 6 秒是演示值，真实会话通常 15~30 分钟，不是性能结论。

## 5. 追问与边界（面试高频）

- Q: 为什么不用一个布尔值表示过期？ → A: 布尔值只有「没过期 / 过期」，没有提前警告；用户看到提醒时已经来不及保存。
- Q: 警告态还能不能点页面其他操作？ → A: 可以保留只读浏览，但提交类操作应引导先续期；本案例为了看清状态机，只保留「继续使用」和「退出登录」。
- Q: 过期后表单内容怎么办？ → A: 本地草稿先存起来，重新登录后恢复；只提示「已过期」会让用户白填一遍。

踩坑（≤3 条）：

1. 只显示倒计时数字、不切阶段：到 0 按钮还能点，点了没反应 → 阶段驱动界面。
2. 任何点击都重置倒计时：警告永远不出现 → 活动只在活跃阶段生效。
3. 组件卸载不清定时器：路由切走后回调继续跑 → 卸载时统一停表。

边界：多标签页同步、服务端刷新令牌、网络断开重连不在本例范围；真实项目里续期通常要调接口，失败时要回到警告态而不是假装成功。
