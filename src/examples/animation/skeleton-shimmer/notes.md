# 骨架屏微光加载

## 1. 现象 / 场景

异步内容还没回来时，页面只放一个转圈图标；内容一到整块替换，内容区高度从很小突然撑大，下方正文被往下顶。用户刚滚到的位置丢了，连续刷新几次会觉得页面一直在跺脚。

复现步骤：

1. 打开案例，保持默认的「转圈（旧）」模式，点「模拟加载（1.2s）」。
2. 等待内容出现：面板里的「布局跳动次数」记为 1，「替换前 → 替换后」两个高度差出一大截，下方虚线块被顶下去。
3. 切到「骨架屏（推荐）」模式再点一次：灰块一开始就按成品排版占好位置，替换前后高度一致，跳动次数为 0。
4. 点「重置」可随时清零重测。
5. 点「模拟减少动态效果」可以看到真实项目在系统开启该设置时应该怎么降级：灰块上的高光静止、骨架直接移除、不做淡出，统计区「动画」显示「跳过」。系统真的开启该设置时，演示区顶部会出现一行提示，本案例为了让高光看得见仍然播放。

## 2. 原理

浏览器渲染一帧要经过样式计算、布局、绘制。加载态的高度与成品不同时，内容替换会让布局重新计算：下方元素的位置整体改变，这就是布局跳动。它不是「动画不好看」，而是真实的位置变化。

转圈方案的问题在于只描述了「正在加载」，没有描述「加载完占多大地方」。占位高度是转圈图标的几十像素，成品却是头像、标题、三行正文加按钮，两者不在一个量级，替换必然推动后续内容。

骨架屏把最终排版的尺寸提前搬到加载态：头部固定 2.5rem、正文每行固定 1rem、底部固定 2rem，骨架块与成品共用同一套盒子和间距。于是替换时只有颜色和文字在变，高度没有变化，浏览器不需要重新安排下方元素。

高光用 `background-image` 的渐变加 `background-position` 位移实现。位移只触发重绘，不触发重新布局；相比改宽度或改内边距的动效，代价更小。内容到位后骨架改成绝对定位并淡出透明度，高度已经完全由成品接管，所以淡出期间也不会引起跳动。

`getBoundingClientRect()` 会强制浏览器先结算布局再返回尺寸，因此脚本量到的是真实渲染高度，而不是样式里写的理论值。这也是为什么测量要放在内容替换前后的两个明确时刻，而不是随手在某个延迟回调里读一次。

## 3. 方案：关键代码

以 `finishLoad` 与 `.sk`（Demo.vue）定位：

```ts
async function finishLoad(): Promise<void> {
  // 为什么先量一次：这是「替换前」的基准，必须早于内容挂载
  beforeHeight.value = measureStage()
  if (mode.value === 'skeleton') skeletonFading.value = true
  phase.value = 'ready'

  await nextTick()
  // 为什么等 nextTick：页面节点已更新，此时读高度才是替换后的真实结果
  afterHeight.value = measureStage()

  // 为什么用 2px 容差：字体亚像素与边框取整会造成 1px 级噪声，不能算跳动
  heightDelta.value = Math.abs(afterHeight.value - beforeHeight.value)
  jumpCount.value = heightDelta.value > 2 ? 1 : 0
}
```

```css
.sk {
  /* 为什么用 background-position：只重绘不重排，加载动画不干扰布局 */
  background-image: linear-gradient(
    100deg,
    transparent 20%,
    color-mix(in srgb, var(--primary) 22%, transparent) 50%,
    transparent 80%
  );
  background-size: 220% 100%;
  animation: shimmer 1.15s linear infinite;
}

/* 为什么降级时直接去掉高光：动效不该是理解加载状态的唯一线索 */
.sk-demo.is-static .sk {
  animation: none;
  background-image: none;
}
```

真实项目里把 `is-static` 换成「检测到系统减少动态效果」的判断即可（媒体查询或脚本都可以）。本案例为了让手机与开启该设置的电脑也能看到高光，把系统设置降级成一条顶部提示，改由「模拟减少动态效果」开关控制这个类，并用一段媒体查询把站点全局压短的动画时长还原。

## 4. 数据对比

| 指标 | 转圈（旧） | 骨架屏（新） | 测量方式 |
|------|------------|--------------|----------|
| 布局跳动次数 | 1 次 | 0 次 | 替换前后各读一次内容区 `getBoundingClientRect().height`，差值超过 2px 记 1 次 |
| 替换前后高度 | 加载态明显矮于成品 | 两者一致 | 面板实时显示「替换前 / 替换后 / 高度差」 |
| 加载态占位块数量 | 0 个（只有图标） | 8 个（头像、标题、说明、三行正文、两个按钮） | 查看骨架层里带 `sk` 类的节点数量 |
| 高光动画声明 | 无 | 1 条 `animation` | 在开发者工具里看 `.sk` 的计算样式 |
| 模拟降级（开关） | 打开后转圈动画停止 | 高光静止、骨架直接移除 | 点「模拟减少动态效果」后复查 `.sk` 的计算样式与统计区「动画」读数 |

测量说明：

- 指标定义：「布局跳动次数」指内容替换这一瞬间，内容区高度差超过 2px 的次数；只统计替换前后两个时刻，不把点击按钮引起的面板高度变化算进去。
- 采集方式：`getBoundingClientRect()` 读取内容区高度（会强制结算布局），前后相减。
- 数据规模：一块卡片，1 个头像、1 行标题、1 行说明、3 行正文、2 个按钮。
- 环境：桌面浏览器与手机视口均可；不同视口下具体高度不同，但「转圈跳、骨架不跳」的结论不变。
- 取样：点「重置」后重复测 3 次；骨架屏的高度一致性由固定行高保证，不依赖字号、字体加载。
- 本档不写死具体像素值，实际数字以 Demo 面板为准。

## 5. 追问与边界

**Q：骨架屏和「加载中」文字提示，该选哪个？**
内容结构固定、排版可预知时用骨架屏，用户能提前建立空间预期；结构不确定、只有一句状态时用文字或转圈更诚实。两者都要有可读的状态说明，不能只靠动画。

**Q：为什么不用固定高度容器把高度锁死？**
固定高度会牺牲内容自适应性：内容变长就被裁切，变短又留下空白。骨架屏复刻的是最终排版，而不是随手写一个死高度。

**Q：高光动画会不会影响性能？**
它只改背景图位置，属于绘制阶段的工作，不触发布局；但大面积、长时间的高光在低端设备上仍会耗电，通常控制在骨架出现的短暂窗口内。真实项目在系统开启「减少动态效果」时应直接去掉动画；本案例为了让高光看得见仍然播放，打开「模拟减少动态效果」开关就能看到降级后的样子。

**Q：骨架屏要等多久才出现？**
如果请求很快返回，先闪一下骨架再出现内容反而更晃眼。常见做法是延迟一小段时间再显示骨架，或让骨架至少停留一小段时间；这个案例为了对比测量，直接在点击后立刻进入加载态。

踩坑：

1. 触发条件：骨架块与成品的行高、间距、边框不一致 → 现象：替换时仍会跳 1~2px 甚至更多 → 修法：两者共用同一套固定盒子（本案例头部、行高、底部都写死）。
2. 触发条件：在高光位移的同时改元素宽度 → 现象：每次动画都触发重新布局 → 修法：只改 `background-position`，尺寸保持不动。
3. 触发条件：骨架淡出时直接 `v-if` 移除 → 现象：内容还没完全显示就出现空白闪一下 → 修法：内容先挂载，骨架改成覆盖层淡出后再移除，并保留兜底计时器。

边界：本案例的「跳动次数」是行为指标，不对应真实网络与真实图片；若页面内容高度本身不可预知（用户自由排版、富文本），骨架只能做近似占位，不能保证 0 跳动。此时应把骨架做成「近似结构 + 稳定最小高度」，并把真实测量结果写进验收记录。
