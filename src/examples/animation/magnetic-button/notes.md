# 磁性按钮：指针跟随微交互

## 1. 现象 / 场景

按钮只有 hover 换背景这一种反馈：指针移到按钮上、在按钮里来回滑动，除了颜色变化什么也不会发生。做作品集或营销页时，这种按钮会显得「木」；但一上来就做跟随，又容易让按钮跟着指针乱跑，点起来像在追目标。

复现步骤：

1. 打开案例，默认是「只换背景（旧）」：把指针移到按钮上左右移动，位移读数一直是 `0px / 0px`，跟随次数一直是 0。
2. 切到「指针跟随（推荐）」：在虚线范围里移动指针，位移读数开始变化，几何读取次数与跟随次数同步上涨。
3. 把强度从「弱」切到「强」：最大位移读数会变大，但始终停在该档上限（弱 4px / 中 8px / 强 14px），不会无限跟下去。
4. 指针移出虚线范围：按钮缓动回弹到中心，位移回到 `0px / 0px`。
5. 点「重置」恢复初始状态，再测一轮。

## 2. 原理

跟随的本质是「把指针相对按钮中心的位置，缩成一个很小的位移」。指针坐标由指针事件的 `clientX` / `clientY` 给出，按钮中心由 `getBoundingClientRect()` 的左上角加一半宽高得到；两者相减就是指针偏离中心的距离。乘一个小于 1 的系数（案例里是 0.12 / 0.24 / 0.4），按钮只会动一小段，不会真的追着指针跑。

位移要写到 `transform` 上，而不是 `left` / `top` / `margin`。改 `left` 会进入布局流程，每一帧都要重新排版；`transform: translate()` 只影响合成，浏览器可以把按钮放到单独的图层里平移，页面其他内容不用重排。案例把位移写进两个 CSS 变量 `--mx` / `--my`，样式里统一用 `translate3d(var(--mx), var(--my), 0)` 消费，脚本与样式职责分开。

跟随时不能给 `transform` 加过渡，否则按钮会慢半拍，指针已经移开了按钮才跟上；回弹时才打开过渡，让按钮自己滑回中心。这两个状态用 `is-returning` 类区分，而不是在脚本里逐帧插值。

跟随要设上限。指针可能在按钮外很远的地方，偏移乘以系数后仍可能很大，所以每一轴都要夹到 ±上限；上限同时也保护了布局，按钮不会被甩到磁力范围外压住别的元素。触摸设备不跟：手指按住按钮时页面本来就在滚动或点击，再叠一层位移会让人以为点错了。系统开启「减少动态效果」时也不跟，这是对用户偏好的尊重。

`pointermove` 与 `pointerleave` 挂在按钮外围的「磁力范围」上，而不是按钮本身。这样指针在按钮旁边（范围之内）也能带动按钮，符合「磁性」的直觉；同时指针离开范围就立刻回弹，不需要额外判断距离阈值。

## 3. 方案：关键代码

以 `onPointerMove`、`onPointerLeave` 与 `.mag-btn`（Demo.vue）定位：

```ts
function onPointerMove(event: PointerEvent): void {
  if (mode.value !== 'on') return
  if (reducedMotion.value) return

  // 为什么在这里拦触摸：手指按住时按钮位移会被误认为点击抖动
  if (event.pointerType !== 'mouse') {
    touchSkipped.value++
    return
  }

  // 为什么每次都读矩形：按钮可能随页面滚动、窗口变化，缓存会过期
  geoReads.value++
  const rect = buttonRef.value!.getBoundingClientRect()

  // 指针相对按钮中心的偏移 × 强度系数，再夹到单轴上限
  const { factor, max } = currentStrength.value
  const nextX = round1(clamp((event.clientX - (rect.left + rect.width / 2)) * factor, max))
  const nextY = round1(clamp((event.clientY - (rect.top + rect.height / 2)) * factor, max))

  // 为什么这里关掉回弹：跟手阶段有过渡会明显慢半拍
  returning.value = false
  offset.value = { x: nextX, y: nextY }
}

function onPointerLeave(): void {
  // 为什么只写 0 不逐帧算：回弹的中间帧交给样式过渡
  returning.value = true
  offset.value = { x: 0, y: 0 }
}
```

```css
.mag-btn {
  /* 为什么用变量：脚本只改这两个值，transform 写法集中在一处 */
  --mx: 0px;
  --my: 0px;
  transform: translate3d(var(--mx), var(--my), 0);
  transition: background-color var(--transition), box-shadow var(--transition);
}

/* 为什么只在回弹时开过渡：跟手时要即时，回弹时要柔和 */
.mag-btn.is-returning {
  transition: transform 0.3s var(--ease-out),
    background-color var(--transition), box-shadow var(--transition);
}
```

## 4. 数据对比

| 指标 | 只换背景（旧） | 指针跟随（新） | 测量方式 |
|------|----------------|----------------|----------|
| 指针移动后的位移读数 | 恒为 `0px / 0px` | 随指针变化，最大不超过该档上限 | Demo 面板的「当前位移」 |
| 跟随次数 | 0 次 | 每次指针移动加 1 | Demo 面板的「跟随次数」 |
| 每次移动读取按钮矩形 | 0 次 | 1 次 | Demo 面板的「几何读取」 |
| 与位移相关的逻辑函数 | 0 个（只有样式 hover） | 2 个（移动 / 离开） | 数脚本里的指针处理函数 |
| 触摸指针行为 | 只有背景反馈 | 跳过跟随并计数 | 手机或触屏设备上按住滑动 |
| 位移上限 | 不存在位移 | 弱 4px / 中 8px / 强 14px | 切档后看「本轮最大位移」 |
| 减少动态效果 | 不受影响 | 直接不跟随 | 系统设置里开启后移动指针 |

测量说明：

- 指标定义：「位移」指按钮实际平移的像素值；「跟随次数」指指针移动触发位移计算的次数；「几何读取」指调用 `getBoundingClientRect()` 的次数。
- 采集方式：Demo 内的计数器与读数直接来自运行时，不需要打开开发者工具；位移读数由脚本写入前记录。
- 数据规模：单个按钮、三档强度；指针移动次数由用户操作决定，没有固定样本量。
- 环境：桌面鼠标与触屏设备各测一次；触屏上关注「触摸跳过」是否上涨。
- 取样：重置后在同一块区域内左右移动若干次，观察三个计数是否同向增长。
- 本案例不宣称耗时或帧率差异：比较的是「有没有空间反馈、要不要每次读几何、触摸是否被排除」，不涉及动画性能的数字。

## 5. 追问与边界（面试高频）

**Q：为什么不用 `mousemove`，而用 `pointermove`？**
`pointer` 事件同时覆盖鼠标、手指、触控笔，并且事件对象里有 `pointerType`，可以直接判断要不要跟随；`mouse` 事件在触摸设备上还有一段兼容映射，容易出现手指拖动也被当成鼠标移动的情况。用一套指针事件就能把「鼠标跟随、触摸不跟随」写在一个入口里。

**Q：为什么位移用 CSS 变量，而不是直接写 `style.transform`？**
两者都能动，但变量把「算出来的数值」与「怎么用」拆开了：样式里可以同时消费 `--mx` / `--my` 做 `translate3d`，也可以顺手做光晕、阴影的联动，而脚本不需要知道最终的 transform 语法。变量也让调试更直观，开发者工具里直接改数值就能看到效果。

**Q：为什么不把监听挂在按钮上，而是挂在外围容器上？**
挂在按钮上只有指针进入按钮矩形才会触发，按钮旁边的区域没有反馈，看起来像「贴上去才动」。挂在外围磁力范围上，指针靠近就能带动按钮，离开范围才回弹，手感更连贯；范围大小本身就是可调的设计参数。

**Q：跟随会不会影响点击？**
会，如果位移太大或过渡太慢。位移被夹在十几像素内、回弹不超过 0.3 秒，指针按下时按钮仍在指针下方，点击目标不会跑掉；如果做大幅度跟随，需要保证可点击区域同步移动，或者干脆只在装饰性按钮上使用。

**Q：为什么触摸设备要跳过？**
手指按住按钮时，页面可能正在滚动，按钮再跟着手指平移会让人误以为拖动生效了或点偏了。触摸的反馈更适合用按下缩放、水波纹这类「以触点为圆心」的效果，而不是跟随指针。

踩坑：

1. 触发条件：跟随时也给 `transform` 写了长过渡 → 现象：按钮慢半拍，指针移开后还在追 → 修法：只在回弹状态加 `transition`，跟手时保持无过渡。
2. 触发条件：没有夹取上限 → 现象：指针在范围边缘时按钮被甩出容器，压住旁边的文字 → 修法：每一轴都夹到 ±上限，并让容器裁掉意外溢出。
3. 触发条件：用 `left` / `top` 写位移 → 现象：移动时页面其他内容跟着抖动，长列表尤其明显 → 修法：改用 `transform: translate3d()`，只走合成。

边界：本方案适合按钮、卡片、头像这类小面积元素；大面积跟随会让人晕，也不适合表单输入区域。指针跟随不是必需的交互增强，键盘用户与触摸用户本来就用不到，所以默认状态、关闭开关与减少动态效果都必须完整可用。
