# SVG 进度环

## 1. 现象 / 场景

上传或加载时用一个圆环表示进度，代码里开一个定时器，每隔十几毫秒把偏移量改一点。进度看起来在走，但计时逻辑和业务逻辑混在一起；组件切走时忘了停，定时器还在后台空转。想改成「跳到 60%」也要自己补中间帧。

复现步骤：

1. 打开案例，保持「定时器逐帧（旧）」，点「重置」再点「开始」：进度从 0 走到 100，「属性写入次数」一路累加，定时器状态显示运行中。
2. 切到「样式过渡（推荐）」，再点「重置」和「开始」：进度同样走到 100，但属性只写了一次，定时器显示「无」。
3. 拖动滑杆或点 25%、60%、100%：两种方式都能到目标值，旧方式靠逐帧靠近，新方式靠样式过渡。
4. 系统开启「减少动态效果」后重试：两种方式都直接跳变，不再有中间过程。

## 2. 原理

圆环用 SVG 的圆表示。描边默认画整圈，`stroke-dasharray` 把描边切成「一段实线 + 一段空白」，当实线长度等于圆周长时就是完整一圈；`stroke-dashoffset` 再把这个图案沿路径平移。把周长写进 dasharray，把偏移量从「整圈长度」调到 0，视觉上就是圆环从空到满。

周长由半径算出：半径 52 时周长约为 326.73。进度 0% 时偏移量等于周长，整圈都是空白；进度 100% 时偏移量为 0，整圈都是实线。中间任意百分比都只是同一个公式的结果，不需要额外状态。

`stroke-dashoffset` 是一个样式属性，可以在两个数值之间过渡。脚本只负责把目标值写进去，浏览器在样式计算阶段自己插值，逐帧更新画面。旧做法反过来：脚本每个周期把值加一点，浏览器每收到一次新值就重绘一次。前者把「补中间帧」的工作交给了渲染管线。

圆环默认从三点钟方向开始画，所以整个画布要旋转 -90 度，让起点落到十二点钟方向。旋转放在最外层画布上，圆环与轨道一起转，中心的百分比文字放在画布外的覆盖层里，不会被转倒。

定时器方案的问题不只是代码更长：它需要自己保证「什么时候开始、什么时候停、卸载时清不清理」，而这些点很容易在条件分支里漏掉。样式过渡只需要在切换时写一次值，清理点只剩「重置时临时关闭过渡」这一处。

## 3. 方案：关键代码

以 `setProgressTarget` 与 `.value.tween`（Demo.vue）定位：

```ts
function setProgressTarget(next: number): void {
  const clamped = Math.min(100, Math.max(0, Math.round(next)))
  target.value = clamped
  stopTimer()

  // 为什么先处理减少动态效果：不做过渡也不逐帧，信息仍然由百分比文字给出
  if (reducedMotion.value) {
    progress.value = clamped
    writes.value++
    return
  }

  if (mode.value === 'transition') {
    // 为什么只写一次：中间帧由 stroke-dashoffset 的过渡补齐
    progress.value = clamped
    writes.value++
    return
  }

  // 为什么旧做法要清定时器：目标一变就重开，避免多个定时器同时改同一个值
  ticking.value = true
  stepTimer = window.setInterval(() => {
    const diff = clamped - progress.value
    if (diff === 0) {
      stopTimer()
      return
    }
    progress.value += diff > 0 ? 1 : -1
    writes.value++
  }, 16)
}
```

```css
.value {
  fill: none;
  stroke: var(--primary);
  stroke-width: 10;
  stroke-linecap: round;
}

.value.tween {
  /* 为什么只声明偏移量：过渡要落在真正变化的属性上，范围越小越可控 */
  transition: stroke-dashoffset 0.8s var(--ease-out);
}
```

```html
  <circle class="value" cx="60" cy="60" r="52" />

```

## 4. 数据对比

| 指标 | 定时器逐帧（旧） | 样式过渡（新） | 测量方式 |
|------|------------------|----------------|----------|
| 从 0 到 100% 的属性写入次数 | 100 次（每次加 1） | 1 次 | 先点重置，再点开始，读面板计数 |
| 定时器数量 | 1 个 | 0 个 | 面板「定时器」状态与代码检查 |
| 需要清理的计时器 | 1 个（切模式、重置、卸载） | 0 个 | 数代码里的清理点 |
| 中间帧由谁补 | 脚本每个周期写一次 | 浏览器样式过渡 | 看驱动方式与代码 |
| 减少动态效果 | 直接跳变 | 直接跳变 | 系统设置开启后复测 |
| 进度文字 | 由同一个进度值渲染 | 同左 | 圆环中心读数 |

测量说明：

- 指标定义：「属性写入次数」指脚本真正把新的偏移量交给组件的次数；「定时器数量」指当前有几个计时器在跑。
- 采集方式：Demo 内计数器与定时器状态实时显示，重置会清零。
- 数据规模：一个圆环、一个进度值、一个滑杆与三个快捷按钮。
- 环境：支持 SVG 与样式过渡的现代浏览器；系统开启减少动态效果时两种方式都走直接跳变的分支。
- 取样：重置后从 0 开始跑到 100 为一轮，重复 3 次，写入次数与百分点数一致；本档不写耗时与帧率。
- 本案例比较的是「谁来补中间帧」与清理成本，不做渲染性能结论。

## 5. 追问与边界

**Q：真实的网络进度可以用样式过渡吗？**
可以。进度事件到达时把当前百分比写成新目标，过渡负责在两次事件之间平滑衔接；事件间隔不均匀时反而比定时器更自然。若事件非常密集，频繁改目标会不断重启动画，可以按时间片合并更新，或直接设置不过渡的当前值。

**Q：为什么不用 SVG 的动画标签直接做？**
声明式动画适合固定循环（比如不确定进度的旋转），但进度是由业务数据驱动的，需要在任意时刻跳到任意值。用样式值加过渡，数据是唯一真源，暂停、重置、减少动态效果都更容易控制。

**Q：`stroke-dashoffset` 过渡会不会触发布局？**
它属于描边绘制，不会改变盒子尺寸，不会触发布局；但每次变化仍要重绘这块区域。圆环面积小，代价可控；如果同时有几十个圆环一起跑，仍应限制数量或降低更新频率。

**Q：减少动态效果时直接把进度跳过去，信息会丢吗？**
不会。百分比文字与 `aria-valuenow` 仍然更新，圆环只是没有中间帧。减少动态效果去掉的是运动，不是状态。

踩坑：

1. 触发条件：`stroke-dasharray` 用的长度与半径算出的周长不一致 → 现象：进度到 100% 时圆环有缺口或首尾重叠 → 修法：周长统一由半径计算，两个值不要各写一份。
2. 触发条件：忘记把整块画布旋转 -90 度 → 现象：进度从三点钟方向开始增长，和常见的十二点起点不一致 → 修法：旋转画布，或给圆加上合适的变换原点。
3. 触发条件：旧做法切换目标时不清除上一个定时器 → 现象：两个定时器同时改进度，速度变快且互相覆盖 → 修法：设置新目标前先停旧计时器。

边界：本案例适合「已知百分比」的进度。不确定进度的等待状态不要硬凑百分比，应该用循环旋转或骨架屏；需要暂停、回退、分段颜色的复杂进度条，样式过渡仍然够用，但要把过渡目标与业务状态分开管理，避免一次更新触发多条过渡。
