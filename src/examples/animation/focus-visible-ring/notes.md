# 键盘焦点环

## 1. 现象 / 场景

为了「好看」，把焦点样式写成 `outline: none`。鼠标用户没感觉，但键盘用户按 Tab 时，焦点在按钮、链接、输入框之间移动，屏幕上没有任何变化——按了回车触发的是哪个按钮，只能靠猜。表单稍微长一点，键盘用户基本没法用。

复现步骤：

1. 打开案例，默认是「无焦点样式（旧）」：按 Tab 键依次经过四个控件，面板里「当前聚焦」会变化，但页面上看不到任何位置提示，「计算后的轮廓」显示 none。
2. 切到「自建焦点环（推荐）」：再按 Tab，每个控件外圈出现 2px 主色轮廓，面板的「计算后的轮廓」显示 solid 2px。
3. 用鼠标点击按钮或链接：焦点确实进入控件，但「键盘触发」显示「否」，轮廓仍是 none。
4. 点一下输入框：多数浏览器会把输入框也当成需要焦点提示的元素，焦点环照常出现——这是按输入意图判断，不是按鼠标/键盘判断。
5. 点「重置」：焦点被移走，模式回到「无焦点样式」，计数清零。

## 2. 原理

`outline` 是浏览器给「当前获得焦点」的元素画的轮廓，默认样式由浏览器决定。它不占布局空间（画在边框外），所以不会把周围内容挤动；这也是它适合做焦点提示的原因。把它写成 `none`，等于告诉浏览器「不要给任何提示」，键盘用户就失去了唯一的位置线索。

`:focus` 与 `:focus-visible` 的区别在「意图」。`:focus` 只要元素获得焦点就匹配，鼠标点击按钮、脚本调用 `focus()` 都会命中；`:focus-visible` 由浏览器根据输入方式判断，用 Tab 键移动、用快捷键进入、输入框准备接收文字时通常匹配，鼠标点击按钮时通常不匹配。于是同一套轮廓样式写在 `:focus-visible` 上，键盘用户看得到，鼠标用户不会被额外画一圈。

输入框是常见的例外：浏览器预期用户随时会打字，所以鼠标点击输入框也可能匹配 `:focus-visible`。这不是 bug，而是它认为「这里需要焦点提示」。因此不能用「鼠标点击一定不出现焦点环」当作验收标准，验收要看具体控件与浏览器。

轮廓与阴影是两种画法。`outline` 不参与布局、不影响圆角（轮廓本身是矩形），但可以用 `outline-offset` 让它离开边框几个像素，避免贴着边框显得脏；`box-shadow` 能贴合圆角、能做多层光晕，但它属于盒子阴影，可能被父级的 `overflow: hidden` 裁掉，也会被其他阴影覆盖。做无障碍焦点环时优先 `outline`，需要更复杂的效果再叠加阴影。

焦点样式还要考虑对比度：在主色按钮上再画主色轮廓，边界会糊在一起。案例用 `outline-offset: 2px` 把轮廓推到按钮外面，轮廓与按钮之间留出页面底色，对比就清楚了。焦点环的粗细建议不低于 2px，太细在低分辨率屏上会看不见。

## 3. 方案：关键代码

以 `.stage`、`onFocusIn`（Demo.vue）定位：

```css
.stage.no-ring :focus {
  /* 旧做法：所有焦点提示一并关掉，键盘用户失去位置线索 */
  outline: none;
}

.stage.with-ring :focus-visible {
  /* 为什么用 :focus-visible：鼠标点击按钮时不画，键盘操作时才画 */
  outline: 2px solid var(--primary);
  /* 为什么留偏移：轮廓贴着边框会与按钮背景糊在一起 */
  outline-offset: 2px;
}
```

```ts
function onFocusIn(event: FocusEvent): void {
  const target = event.target
  if (!(target instanceof HTMLElement)) return

  focusCount.value++

  // 为什么用 matches：脚本读不到「浏览器是否画了焦点环」，但能问它是否匹配
  keyboardTriggered.value = target.matches(':focus-visible')

  // 为什么等一帧：焦点样式可能在本次样式结算里才生效
  window.requestAnimationFrame(() => {
    if (document.activeElement !== target) return
    const style = window.getComputedStyle(target)
    const width = Number.parseFloat(style.outlineWidth) || 0
    const visible = style.outlineStyle !== 'none' && width > 0
    outlineText.value = visible ? `${style.outlineStyle} ${width}px` : 'none'
    if (visible) ringCount.value++
  })
}
```

## 4. 数据对比

| 指标 | 无焦点样式（旧） | 自建焦点环（新） | 测量方式 |
|------|------------------|------------------|----------|
| 计算后的轮廓 | `none`，宽度 0px | `solid`，宽度 2px | Demo 面板「计算后的轮廓」，读计算样式 |
| Tab 键移动时是否看得到焦点 | 看不到 | 每个控件都有轮廓 | 按 Tab 走一遍 |
| 鼠标点击按钮时是否画环 | 不画 | 不画（`:focus-visible` 不匹配） | 点击按钮看「键盘触发」 |
| 输入框鼠标点击 | 无 | 多数浏览器会画（按输入意图判断） | 点一下输入框对比 |
| 与焦点样式有关的声明 | 1 条（`outline: none`） | 2 条（`outline` + `outline-offset`） | 数样式块里的声明 |
| 面板能读到的状态 | 无 | 聚焦控件 / 键盘触发 / 轮廓 | Demo 面板三行读数 |
| 焦点进入次数与画环次数 | 进入 N 次，画环 0 次 | 进入 N 次，键盘触发时画环 | Demo 面板两个计数 |

测量说明：

- 指标定义：「计算后的轮廓」指浏览器最终结算出的 `outline-style` 与 `outline-width`；「键盘触发」指焦点元素是否匹配 `:focus-visible`。
- 采集方式：`getComputedStyle()` 读轮廓，`matches(':focus-visible')` 读匹配状态，都在焦点进入后的下一帧执行，避免读到结算前的值。
- 数据规模：4 个控件（按钮、链接、输入框、卡片按钮），覆盖常见可聚焦元素。
- 环境：桌面键盘与鼠标各走一遍；触摸设备上点击不应出现焦点环（输入框除外）。
- 取样：重置后先用鼠标点一遍，再用 Tab 走一遍，对比两个计数与轮廓读数。
- 本案例不宣称性能差异：比较的是「焦点提示是否出现、能否被读到」，没有测渲染耗时。

## 5. 追问与边界（面试高频）

**Q：`:focus` 和 `:focus-visible` 到底差在哪？**
`:focus` 只回答「有没有焦点」；`:focus-visible` 还回答「用户此刻需不需要看到焦点」。鼠标点按钮时元素确实有焦点，但用户刚点过，位置很清楚，浏览器就不匹配 `:focus-visible`；用 Tab 移动时用户需要位置提示，就匹配。把轮廓写在后者，既保留键盘可达性，又不给鼠标用户加视觉噪音。

**Q：为什么不用 `box-shadow` 代替 `outline`？**
`box-shadow` 能贴合圆角、能做多层光晕，但它是盒子阴影：会被父级 `overflow: hidden` 裁掉，也会被其他阴影覆盖，而且不占布局却可能被误认为装饰。`outline` 是浏览器专门为焦点提供的绘制层，语义更明确；需要更花哨的效果时，可以 `outline` 打底再叠阴影。

**Q：那输入框为什么点一下也有焦点环？**
浏览器认为输入框随时准备接收键盘输入，所以把「点击输入框」也视为需要焦点提示。这是规范允许的实现差异，不同浏览器不完全一致。做验收时不要写死「鼠标点击一定没有环」，而要按控件类型分别看。

**Q：设计一定要去掉默认样式怎么办？**
可以改，但不能删。把默认的 `:focus-visible` 换成自定义的 2px 轮廓或双层焦点环，保证与背景有足够对比，并在 `outline-offset` 上留出空隙。团队里最好把这条写进规范：任何 `outline: none` 都必须配一条等价的可见焦点样式。

**Q：老浏览器不支持 `:focus-visible` 怎么办？**
可以渐进增强：先写 `:focus` 的基础轮廓，再用 `:focus-visible` 覆盖成更精细的样式。老浏览器不认识后一条规则会忽略它，仍然保留基础轮廓；新浏览器则拿到「只在需要时出现」的体验。关键是不要出现「两边都没有轮廓」的中间状态。

踩坑：

1. 触发条件：全局写了 `*:focus { outline: none }` 做「美化」 → 现象：所有控件的键盘焦点提示全部消失，组件里再写 `:focus-visible` 也可能被更高优先级覆盖 → 修法：删掉全局关闭，改成 `:focus-visible` 统一定义，组件内只做补充。
2. 触发条件：焦点环用主色画在主色按钮上，且 `outline-offset: 0` → 现象：轮廓与按钮背景连成一片，等于没画 → 修法：留 2px 偏移，让轮廓与按钮之间露出页面底色。
3. 触发条件：用 `box-shadow` 画焦点环，父级有 `overflow: hidden` → 现象：环被裁掉一半，看起来像样式错位 → 修法：优先用 `outline`，或把裁切改到更内层。

边界：`:focus-visible` 只对「可聚焦元素」生效，`div` 不写 `tabindex` 永远拿不到焦点，先解决可聚焦再谈焦点样式。焦点环属于无障碍底线，不适合为了「好看」而完全隐藏；如果设计坚持，至少保留 `:focus-visible` 的替代样式。触摸设备上通常不需要焦点环，但外接键盘的平板仍会用到，所以不要按设备类型一刀切。
