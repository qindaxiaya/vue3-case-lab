# 滚动吸附轮播

## 1. 现象 / 场景

卡片轮播里，圆点跳转是「索引 × 卡片宽 + 间距」算出来的：卡片宽度一改、间距一调、容器里多了一层内边距，最后一张就会差一截；如果再忘了把目标位置夹到最大可滚动范围，点最后一个圆点会滚过头或滚不到。手指滑动更明显：松手后停在两张卡片中间，既不像第一张也不像第二张。

复现步骤：

1. 打开案例，默认是「手算 scrollLeft（旧）」：点圆点跳转，面板会显示手算的「目标距离 → 夹取后距离」，两处都需要脚本自己算。
2. 在轮播上用手滑一段再松手：卡片会停在任意位置，「居中误差」读数大于 0，索引显示的是四舍五入后的那一张。
3. 切到「滚动吸附（推荐）」：再滑一段，松手后卡片自动吸到中间，居中误差回到 0。
4. 点圆点或左右箭头，观察「本次手算距离」变成 0 处，手算结果一栏显示「浏览器自己算」。
5. 聚焦轮播后按左右方向键，行为与箭头一致。
6. 点「模拟减少动态效果」：开关变成「模拟中：已降级」，再点圆点或箭头，滚动直接到位、不再平滑推进；吸附仍然生效，卡片照样停在正中。

## 2. 原理

滚动吸附是滚动容器自带的能力，不需要脚本参与。容器上的 `scroll-snap-type: x mandatory` 表示「横向按强制吸附」，子项上的 `scroll-snap-align: center` 表示「把这一项的中心对到容器中心」。滚动结束（或程序化滚动结束）时，浏览器会挑选最近的对齐点并修正位置；用户滑到两张之间松手，也会被吸到较近的一张。这属于滚动行为，不依赖指针事件，也不依赖 `scroll` 监听。

`scrollIntoView({ block: 'nearest', inline: 'center' })` 是另一个方向的委托：告诉浏览器「把这张卡片滚进可视区并横向居中」。它知道容器的内边距、滚动范围与当前缩放，所以最后一张卡片能不能居中、目标位置要不要夹取，都由浏览器判断，脚本不需要再算。`block: 'nearest'` 的意思是纵向不要乱动——轮播只关心横向，页面高度不该因为一次跳转被改变。

索引仍然要自己算，但可以从「状态」退化成「读数」：滚动位置除以单卡滚动距离（卡片宽 + 间距），四舍五入就是当前卡片。这样就不需要维护 `prevIndex` / `nextIndex` 两套状态，也不会出现「点了圆点但索引没更新」的错位。单卡距离要从布局里量，不能写死：窗口宽度变化后卡片宽度会变。

要让第一张与最后一张也能居中，滚动容器首尾必须留白，宽度等于「容器宽 − 卡片宽」的一半。案例用 `::before` / `::after` 两个弹性占位实现，占位宽度里减掉一个间距，抵消占位与卡片之间的 gap。留白是吸附能对齐首尾的前提：没有留白时，最后一张只能停在滚动尽头，中心永远对不上容器中心。

索引从滚动位置换算，前提是「第 0 张居中时滚动位置正好是 0」。首尾留白正好让这件事成立，所以 `scrollLeft / 单卡距离` 的整数部分才是卡片序号；如果留白写错，吸附仍然工作，但索引会整体偏移。

平滑滚动属于装饰：系统开启「减少动态效果」时，真实项目应当据此降级，把 `scrollIntoView` 与 `scrollTo` 的 `behavior` 换成 `auto`，让滚动直接到位；吸附必须保留，因为它决定「停在哪」，是功能不是动画。本案例为了让平滑滚动看得见，演示默认仍然播放；点「模拟减少动态效果」可以切到降级分支。

## 3. 方案：关键代码

以 `goTo`、`readMetrics`（Demo.vue）与 `.track` 定位：

```ts
function goTo(target: number): void {
  const track = trackRef.value!
  const nextIndex = Math.min(SLIDES.length - 1, Math.max(0, target))
  const behavior: ScrollBehavior = reducedMotion.value ? 'auto' : 'smooth'

  if (mode.value === 'manual') {
    const step = measureStep()
    const maxLeft = track.scrollWidth - track.clientWidth
    // 为什么第 1 处手算：自己算目标位置，就必须知道单卡占多少滚动距离
    const wanted = Math.round(step * nextIndex)
    // 为什么第 2 处手算：不夹取的话，最后一张的目标位置会超过可滚动上限
    const clamped = Math.max(0, Math.min(wanted, maxLeft))
    track.scrollTo({ left: clamped, behavior })
  } else {
    // 为什么不用算距离：对齐点与滚动范围都交给浏览器
    getSlides()[nextIndex]?.scrollIntoView({
      block: 'nearest',
      inline: 'center',
      behavior,
    })
  }
}

function readMetrics(): void {
  const track = trackRef.value
  if (!track) return
  const step = measureStep()
  // 为什么从位置反推：滚动是唯一事实来源，索引只是它的读数
  index.value = Math.round(track.scrollLeft / step)
}
```

```css
.track {
  /* 为什么留白要对半分：卡片居中时左右剩余空间必须相等 */
  display: flex;
  gap: var(--gap);
  overflow-x: auto;
}

.track::before,
.track::after {
  /* 为什么减掉一个 gap：占位与卡片之间也会产生间距 */
  content: '';
  flex: 0 0 calc((100% - var(--card-w)) / 2 - var(--gap));
}

.is-snap .track {
  /* 为什么 mandatory：用户松手就对齐，不留下半张卡片的中间态 */
  scroll-snap-type: x mandatory;
}

.slide {
  flex: 0 0 var(--card-w);
  /* 为什么写在子项上：容器决定方向，子项决定对齐点 */
  scroll-snap-align: center;
}
```

## 4. 数据对比

| 指标 | 手算 scrollLeft（旧） | 滚动吸附（新） | 测量方式 |
|------|----------------------|----------------|----------|
| 圆点跳转需要手算的距离 | 2 处（目标距离 + 边界夹取） | 0 处 | Demo 面板「本次手算距离」 |
| 手算中间结果 | 显示「目标 → 夹取后」像素值 | 显示「浏览器自己算」 | Demo 面板「手算结果」 |
| 自由滑动停下后的居中误差 | 常大于 0 | 停稳后为 0 | Demo 面板「居中误差」，滚动事件停稳 160ms 后量 |
| 跳转函数里与距离有关的语句 | 6 行左右（量卡片、算目标、夹边界、调用） | 1 行（scrollIntoView） | 数 `goTo` 里的语句 |
| 索引来源 | 滚动位置换算 | 滚动位置换算 | 两种模式共用 |
| 键盘左右键 | 可用 | 可用 | 聚焦轮播后按方向键 |
| 首尾卡片能否居中 | 取决于留白与夹取是否写对 | 由对齐点与留白保证 | 点第一个 / 最后一个圆点看居中误差 |

测量说明：

- 指标定义：「手算距离」指跳转前脚本自己计算滚动位置的次数；「居中误差」指当前卡片中心与轮播容器中心的水平像素差。
- 采集方式：「手算距离」由跳转分支累加并在面板显示；「居中误差」用 `getBoundingClientRect()` 比较卡片中心与容器中心，滚动停稳后再量，避免量到动画中间帧。
- 数据规模：5 张卡片，窄屏卡片宽度为容器的 76%，宽屏固定 18rem，间距 0.75rem。
- 环境：桌面鼠标与 375px 视口各试一次；触屏设备上直接用手滑，观察松手后的吸附。
- 取样：同一次滑动重复几次，旧做法停下的位置每次不同，新做法每次都停在整张卡片。
- 本案例不宣称耗时差异：比较的是「要不要手算距离」「停下时对不对齐」，没有测帧率或滚动耗时。

## 5. 追问与边界（面试高频）

**Q：`scroll-snap-type` 与 `scroll-behavior: smooth` 冲突吗？**
不冲突，但不要同时依赖两者。`scroll-behavior` 决定「怎么滚过去」，吸附决定「停在哪」。程序化跳转时显式传 `behavior` 更可控；减少动态效果时，真实项目应当据此降级，把 `behavior` 换成 `auto`，让滚动立即到位，吸附仍然生效（吸附是布局行为，不受动态效果偏好影响）。本案例为了让平滑滚动看得见，演示默认仍然播放；点「模拟减少动态效果」可以查看降级行为。

**Q：为什么索引不用 IntersectionObserver？**
可以用，但轮播通常只需要「当前第几张」，滚动位置除以单卡距离就够了，一次减法一次除法，不需要额外的观察器与回调。IntersectionObserver 更适合「元素是否进入视口」这类与滚动位置不成线性关系的问题。

**Q：为什么首尾要加占位，不能只用 padding？**
`padding-inline` 也能留出空间，但百分比内边距的参照宽度与卡片百分比宽度的参照宽度容易算拧：卡片宽度百分比参照的是滚动容器的内容盒，内边距百分比参照的是包含块，两边对不上就会出现「第一张居中、最后一张偏一点」。用两个弹性占位，占位与卡片共用同一套百分比参照，公式更好核对。

**Q：键盘用户怎么操作轮播？**
容器加 `tabindex="0"` 与可读的 `aria-label`，监听左右方向键调用同一个跳转函数；圆点用按钮而不是装饰元素，并给每个圆点写清「跳到第几张」。焦点进入轮播后，方向键换卡、Tab 键离开，符合常见的列表式交互预期。箭头按钮在首尾禁用，避免点了没反应。

**Q：卡片数量很多时要注意什么？**
不要一次性渲染几百张卡片。滚动吸附只解决对齐，不解决渲染成本；卡片多时应该配合虚拟滚动，只渲染视口附近的几张。另外强制吸附在长列表里可能让用户「滑不动」，此时可以用 `proximity` 代替 `mandatory`，只在靠近对齐点时才吸。

踩坑：

1. 触发条件：容器没有首尾留白 → 现象：第一张贴着左边、最后一张贴右边，`scrollIntoView` 居中后索引仍对得上但视觉不对 → 修法：补 `::before` / `::after` 占位，宽度为「容器宽 − 卡片宽」的一半再减一个间距。
2. 触发条件：卡片宽度写死像素，窄屏超出容器 → 现象：页面出现横向滚动条，整站被撑宽 → 修法：卡片宽度用百分比或 `min()`，滚动容器自身 `overflow-x: auto`，外层限制 `max-width: 100%`。
3. 触发条件：只监听 `scroll` 却把索引存在另一个变量里 → 现象：程序化跳转后索引与画面不同步 → 修法：索引永远从 `scrollLeft` 反推，跳转后等滚动停稳再量一次。

边界：滚动吸附适合横向卡片、图片走廊、步骤条这类「一张一张看」的布局；不适合需要精确自由定位的画布、时间轴。强制吸附在内容很少时会让滑动显得「黏」，可以按内容量在 `mandatory` 与 `proximity` 之间取舍。旧做法并非不能用，只是每次卡片尺寸或间距变化都要重新核对那两处手算。
