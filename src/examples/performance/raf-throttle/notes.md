# 逐帧合并高频渲染（requestAnimationFrame）

## 1. 现象与场景

让元素跟随鼠标移动，就在鼠标移动事件里直接改位置。鼠标一动，元素一顿一顿，页面发烫；在低配机器上更明显。

复现：打开案例，在虚线框里来回移动鼠标。事件数很快涨到几百，渲染帧数每分钟只增加约 60。

## 2. 原理

鼠标移动事件的触发频率高于屏幕刷新：一秒可能几百次，而屏幕一秒只画 60 次左右。如果每个事件都改一次界面，同一帧内的几十次改动最终只显示最后一次，前面的工作全浪费。

做法是「合并」：事件里只记最新值，并用一个布尔开关保证本帧只预约一次逐帧回调（`requestAnimationFrame`）；回调执行时才真正写入界面。这样每帧最多渲染一次，工作量从「事件数」降到「帧数」。

## 3. 关键代码

```ts
let latestX = 0
let pending = false

function onMouseMove(e: MouseEvent) {
  // 1. 事件里只暂存，绝不直接渲染
  latestX = e.offsetX
  if (pending) return
  pending = true
  // 2. 本帧所有事件共享这一次回调
  requestAnimationFrame(() => {
    pending = false
    // 3. 此刻才真正写入界面，读的是最新值
    dot.style.transform = `translateX(${latestX}px)`
  })
}

// 4. 卸载时取消挂起的回调，否则会操作已销毁的元素
onUnmounted(() => cancelAnimationFrame(rafId))
```

## 4. 数据对比

| 指标 | 直接渲染 | 逐帧合并 |
|---|---|---|
| 每秒更新次数 | 数百（随事件频率） | 约 60（随刷新率） |
| 每帧重复写入 | 几十次，只有最后一次生效 | 1 次 |
| 页面表现 | 掉帧、发烫 | 跟手、稳定 |

测量方式：在虚线框内来回移动鼠标约 3 秒，对比「事件数」和「渲染帧数」两个计数。不同设备的鼠标采样率不同，比值会有差异，但渲染帧数始终受刷新率限制。

## 5. 追问与边界

**Q：和防抖、节流工具函数有什么区别？**
防抖 / 节流按固定时间窗口合并，逐帧合并跟随屏幕刷新节奏，视觉上更平滑，也不会出现「窗口边界刚好没渲染」的空档。

**Q：为什么坐标要用普通变量暂存？**
响应式变量一写就触发更新，等于没合并。暂存到普通变量，等回调里再写进响应式状态，才能一帧只更新一次。

**Q：滚动事件也这样处理吗？**
可以。滚动、窗口尺寸变化、拖拽移动都属于高频事件，都可以「只存值 + 一帧一次写界面」。

坑：只设 `pending = true` 却不重置，会导致后续事件永远被跳过，界面不再更新。边界：需要「每次事件都记录」的场景（如画板连续笔迹）不能合并，应改存点数组再统一绘制。
