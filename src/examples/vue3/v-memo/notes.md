# v-memo 渲染缓存

## 1. 现象与场景

一个 200 行的列表，父组件每秒更新一次时间/无关状态，结果 200 行全部重新 patch。每行数据一点没变，页面却越来越卡。

复现：点「无关更新 tick++」，未开 v-memo 的列表整片重渲染；开启后只有依赖变化的行更新。

## 2. 原理

Vue 默认会 patch 整棵子树。`v-memo` 给一个依赖数组，逐项用 `Object.is` 比较，全部相等就复用旧 vnode，连子组件都不重新渲染，相当于给子树加了一层缓存开关。

它适合「大列表 + 频繁无关更新」；依赖数组必须写全，漏了会显示旧数据。小列表本身 diff 很快，v-memo 的比对开销可能得不偿失。与 `v-once` 的区别：v-once 永久缓存，v-memo 依赖变了会更新。

## 3. 关键代码

```vue
<!-- 1. 只在该行 id/text 变化时重新 patch -->
<div
  v-for="item in list"
  :key="item.id"
  v-memo="[item.id, item.text]"
>
  {{ item.text }} · 渲染 {{ count }}
</div>

<!-- 2. 依赖要覆盖影响该行渲染的所有响应式值 -->
<!-- <div v-memo="[row.id, row.text, theme]"> -->
```

```ts
// 3. 无关状态变化：依赖数组全等 → 整棵子树跳过 patch
tick.value++
```

## 4. 数据对比

| 指标 | 不开 v-memo | 开 v-memo |
|---|---|---|
| 列表行数 | 200 | 200 |
| 初始总渲染 | 200 次（每行 1 次） | 200 次 |
| 无关更新 tick++ | 200 行重渲染 | 0 行重渲染 |
| 随机改一行 | 200 行 patch | 1 行 patch |
| 依赖漏写 | 不会 | 显示旧数据 |

测量方式：Chrome headless 1200×900 打开案例，读取「总渲染 0 次 · 基线 200 行」与每行计数；点「无关更新」/「随机改一行」观察总渲染与行计数变化。计数由 Demo 在渲染时累加。

## 5. 追问与边界

**Q：v-memo 和 computed 有什么区别？**
computed 缓存「值」，v-memo 缓存「vnode 子树」；前者避免重复计算，后者避免重复 patch/渲染。

**Q：依赖数组写 `[item]` 行不行？**
如果 item 是响应式对象且内部属性变化，对象引用可能不变，v-memo 不会更新；写具体字段更安全。

**Q：所有列表都加 v-memo 会更快吗？**
不会。小列表/每行都频繁变化时，比对与维护依赖反而增加成本；先测量再优化。

坑：依赖数组漏了主题、权限等全局值，切换后行不更新。边界：v-memo 不能用在 v-for 之外的多余节点上；Vue 的 patchFlag 已覆盖大部分场景，v-memo 是手动逃生舱。
