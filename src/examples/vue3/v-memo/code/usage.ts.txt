// 重点行用 //! 标记——展示时高亮、复制时自动去标记

// --- 步骤一：v-memo 基本用法（模板指令） ---

// <div v-for="item in list" :key="item.id" v-memo="[item.id, item.text]">
//   <!-- 依赖数组：[item.id, item.text] 任一变化才重新 patch 该子树 -->
// </div>

//! v-memo 是「子树级」缓存：依赖数组逐项 Object.is 比对，
//! 全部相等 → 整棵子树（含子组件）直接复用旧 vnode，跳过 patch。

// --- 步骤二：什么时候用（关键判断） ---

// 1. 大列表（几百~几千行）+ 大部分行内容稳定，只有少数行频繁变化
// 2. 列表行内有昂贵计算/多层嵌套 DOM（跳过 patch 的收益才明显）
// 3. 不要用：小列表（v-memo 本身有比对开销）、每行都频繁变的场景
//
// 注意 v-memo 与 v-once 的区别：
// v-once = 永久缓存（之后永不更新）；v-memo = 依赖驱动缓存（依赖变了就更新）。

// --- 步骤三：依赖数组设计要点 ---

// 依赖数组要覆盖「影响该行渲染的所有响应式值」：
// <div v-memo="[row.id, row.text, theme]">  ← theme 变了这行也该变
// 漏写依赖 = 该值变了行不更新（显示旧数据的 bug 来源）。

// --- 步骤四：与 patch flag 的关系（原理层） ---

// Vue 3 编译模板时会给 vnode 打 patchFlag（如 TEXT = 1, CLASS = 2），
// 更新时按 flag 只 diff 对应 props（精确更新）。
// v-memo 更激进：flag 比对都不做——依赖数组没变直接跳过整棵子树。
// 两者是同一思想的不同层级：编译期 flag 是默认优化，v-memo 是开发者手动加的逃生舱。
