# 运行时按需加载（dynamic-chunk）

> 首个 H1 在详情页会隐藏（页面已有标题），正文从第 1 段开始展示。

## 1. 现象 / 场景

首屏 JS 越滚越大：报表、导出、编辑器这类「可能一整天都不点一次」的功能，和导航、列表一起压进同一个文件。用户在弱网下要先下完这些代码，才能看到第一屏内容。

复现步骤：

1. 打开案例，DevTools 网络面板清空记录
2. 直接刷新页面：三个功能模块（`city-report` / `csv-kit` / `mini-markdown`）一个都不会请求
3. 点「城市人口报表」的「加载并运行」：网络面板立刻出现 2 个新请求，页面统计 19.1 KB
4. 再点一次同一个按钮：新增 0 B，加载耗时从 48 ms 掉到 0.8 ms
5. 切到「全量预载」模式后点「CSV 解析」：只用一个按钮，却一下下载 5 个文件 36.8 KB

## 2. 原理

**静态 import 是「编译期承诺」，动态 import() 是「运行期动作」。** 写在文件顶部的 `import` 会在打包时被当成硬依赖，直接并进当前文件（或它所属的分包）；而 `import()` 是普通函数调用，打包工具看到字符串字面量后，把目标模块单独切一个文件，并把这个调用改写成「插入 script 标签 → 等加载完成 → 返回模块对象」。

**浏览器对模块文件有不止一层缓存。** 同一页面内，模块表（module map）记着已经求值过的模块，第二次 `import()` 直接返回同一个模块对象，不发请求、不重新解析，代价接近 0；跨页面时靠 HTTP 缓存（带指纹的文件名可以长期强缓存，没指纹的走协商缓存，返回 304 只花几百字节头）。所以「首次」和「复访」是两套完全不同的数字，量的时候必须分开说。

**拆包换来的是延迟，不是免费的午餐。** 少下的字节变成了一次点击后的等待：网络往返 + 文件解析 + 模块求值。本地开发服务器上这段只有几毫秒，真实弱网可能是几百毫秒，因此常用功能要做预取（鼠标移入就下载），而不是干等。

**判断标准是「首屏真的用不到吗」。** 首屏要渲染的表格、导航、按钮拆出去只会多一次请求；反过来，只有设置页、导出、图表这类入口明确的功能，拆出去才是净收益。

## 3. 方案：关键代码

```ts
// 摘自 Demo.vue 的 run()
const started = performance.now()

if (mode.value === 'full') {
  //! 错误做法对照：任意按钮都先下载全量入口，三个模块一起到手
  await import('./modules/full-kit')
} else if (key === 'report') {
  //! 分支里写完整字面量：打包工具靠它静态分析，写成变量就失效
  await import('./modules/city-report')
} else if (key === 'csv') {
  await import('./modules/csv-kit')
} else {
  await import('./modules/mini-markdown')
}

const loadMs = performance.now() - started
const runMs = await execute(key)

// 统计「本次新增」的字节：先执行完再读资源计时，避免漏掉最后一个文件
const names = mode.value === 'full' ? FULL_CHUNKS : feature?.chunks ?? []
const { bytes, resourceMs } = collectChunks(names)
```

**为什么 import() 放在点击回调里**：模块下载时机会直接决定首屏体积；放在 `onMounted` 或路由进入时下载，等于换了个地方做预加载，首屏并没有变轻。

**为什么分支写死字面量而不是 `import(path)`**：Vite / webpack 都在构建期扫描字面量来确定拆哪些文件；变量形式只能退化成运行时全量扫描或直接报错。

**为什么统计时要先减去「已经统计过的地址」**：第二次点击命中模块缓存，字节数必须显示 0，才能让人看清「首次 19.1 KB、复访 0 B」的差别；否则数字重复累加会误导。

## 4. 数据对比

同一台机器、Chrome、本地 dev 服务（开发环境按未压缩源码计），每次刷新后点一次「CSV 解析」，取 3 次中位数：

| 指标 | 全量预载（错误） | 按需加载（正确） | 测量方式 |
|------|------------------|------------------|----------|
| 新增下载字节 | 36.8 KB | 7.3 KB | 资源计时 `decodedBodySize` 累加 |
| 请求文件数 | 5 | 1 | 资源条目计数 |
| 点击到可用 | 15 ms | 5.8 ms | `performance.now()` 包裹 `import()` |

其它实测（同环境）：

| 操作 | 新增字节 | 加载耗时 | 说明 |
|------|----------|----------|------|
| 首次点「城市人口报表」 | 19.1 KB / 2 文件 | 48 ms | 报表模块 + 数据集 |
| 首次点「迷你 Markdown」 | 8.5 KB / 1 文件 | 17 ms | 单模块 |
| 同页第二次点「城市人口报表」 | 0 B | 0.8 ms | 命中模块表，无请求 |
| 刷新后再点（协商缓存） | 300 B | 4.7 ms | 304 响应头，不含模块体 |

测量说明：

- 环境：Windows + Chrome，本地 Vite dev 服务，数据规模 80 个城市 / 400 行 CSV
- 开发环境字节是未压缩源码；生产构建会压缩并加指纹，绝对数值更小，但「全量 ≈ 单个的 5 倍」的比例关系不变
- 耗时取自 Demo 面板的 `import()` 前后计时，字节取自浏览器资源计时，均非手写常量

## 5. 追问与边界（面试高频）

- **Q: 动态 import 和路由懒加载是一回事吗？** → A: 同一个机制。路由 `component: () => import()` 就是「路由匹配上了才 import()」，区别只是触发时机由路由决定，而这里由点击决定。
- **Q: 拆得越细越好吗？** → A: 不是。每个文件都有请求头、连接复用、解析的成本；只有几 KB 的模块拆出去常常更慢，通常按「一屏 / 一个重功能」为单位拆。
- **Q: 怎么避免用户点击后等太久？** → A: 预取。鼠标移入或滚动到按钮附近时提前 `import()`，点击时基本已就绪；也可以对高概率功能在首屏空闲时预取，但别把所有模块都预取，那等于没拆。
- **Q: 加载失败怎么办？** → A: 必须给可见的错误提示，并允许再点一次。注意浏览器会记住「这个地址加载失败过」，同一地址再 import 往往立刻失败，真实项目里要换缓存键（加版本参数）或提示刷新页面。

踩坑（≤3 条）：

1. 用变量拼 import 路径 → 构建后该模块没被拆出去，体积没降，报错还难查；改成字面量分支。
2. 统计字节时在 `await import()` 之后立刻读资源计时 → 偶尔漏最后一个文件（全量模式实测少算 7 KB）；改成执行完功能后再统计。
3. 开发环境看到「刷新后只下载 300 B」就以为模块变小了 → 那是 304 协商缓存的响应头，不是模块体积，量体积要禁用缓存或看首次加载。

边界：如果模块在首屏就要显示（比如首屏表格的格式化函数），拆出去只会多一次往返，这类代码应该留在首屏；同理，命中缓存的第二次点击数据不能用来证明「拆包变快了」。本案例的「错误 / 正确对比开关」是「全量预载 / 按需加载」两种模式，在页内切换即可复现，不需要额外条件。
